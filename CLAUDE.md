# identity-access-service: project guide for Claude

GrowerCare IAM (ADR-017: its own repository). It holds users, partner organisations and role grants (role + geography + BU scope), resolves effective principals, and publishes grant events via the outbox.

## Where things are
| Topic | Location |
|---|---|
| Feature specs (rules, examples, traceability) | `docs/specs/iam/` |
| Database schema | `docs/schema.md`; migrations `src/main/resources/db/migration` (dev seed `db/dev-seed`) |
| OpenAPI contract | `contracts/identity-access-service.openapi.json` (regenerated by tests; drift fails CI) |
| Shared libraries | `com.growercare:gc-*` 1.0.0 (growercare-platform-libs) |
| Cross-cutting specs, ADRs | growercare repository |

## Conventions
1. **Authorization:** via gc-security (role + geo + BU scope). An out-of-scope resource returns **404**. Never trust client-supplied scope.
2. **No ORM:** hand-written SQL via `JdbcClient` and named SQL files (ADR-013).
3. **Events only through the outbox** (same transaction). Payloads carry ids and codes only, no PII.
4. **Configuration only from environment variables** (SPEC-PLAT-06):
   - no defaults for hosts, URLs, users, passwords or secrets;
   - every variable is documented in `.env.example`;
   - `ConfigurationHygieneTest` guards both.
5. **Spec-driven development:** spec → parameterized test rows named after spec example IDs → code → green.
6. **Migrations** are expand → migrate → contract. The app role never gets DDL.
7. **Reporting:** run `mvn -B verify` before claiming success.
8. **Git workflow:**
   - never commit to `main`;
   - branch `<type>/<name>`;
   - PR body with `Spec: docs/specs/...`;
   - squash-merge when CI, policy and Claude review are green.
